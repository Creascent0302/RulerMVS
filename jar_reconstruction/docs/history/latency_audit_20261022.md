# 测速可比性审计与六层效率对照

日期：2026-10-22。本文只整理已实际执行的审计和固定权重复测，没有新增训练，也没有重新评测或依据 TEST 选择权重。

**结论：MVSAnywhere 从约 64 毫秒变成约 22 毫秒，主要来自执行优化；此前约 434 毫秒还包含四个参考视角轮换、每参考两遍。三个数字不是相同计算任务。** 本轮同卡逐项复测能够分别复现这些数量级，没有发现最新计时漏掉完整 Hero 主通路的证据。此前若据此直接宣称自研架构更快，比较口径不成立。

## 2. 同一张 5090 的执行路径对照

本轮 GPU 6，PyTorch 2.8.0+cu128，FP32、关闭 TF32、batch=1。三个 DEV 输入帧为 `15937 / 15982 / 16004`；每帧每方案预热 5 次、计时 15 次，每轮轮转执行顺序，计时前后同步 GPU。下表为每方案共 45 次的耗时中位数。

默认四目输入、只输出上相机首遍；输入已在 GPU。时间包含适配器中的输入处理，不含读盘、CPU→GPU 传输、GT 指标或外部点云融合。所有模型共同驻留，本次没有据此声称独立部署峰值显存。

| 运行条件 | 本轮中位数 |
|---|---:|
| 原适配器，慢代价体，保留辅助输出 | 66.03 ms |
| 共享初值封装，慢代价体，保留辅助输出 | 65.27 ms |
| 共享初值封装，官方快速代价体，保留辅助输出 | 28.19 ms |
| 同上，只计算主深度输出 | 26.67 ms |
| 同上，缓存冻结的位置编码 | **22.01 ms** |
| 原适配器，256×448、单上相机两遍 | 122.01 ms |
| 原适配器，256×448、四参考各两遍 | 487.34 ms |
| 原适配器，512×896、单上相机两遍 | 169.83 ms |
| 原自研固定权重，位置缓存关闭 | 72.89 ms |
| 原自研固定权重，位置缓存开启 | 70.31 ms |

“共享初值封装”仍执行完整 MVSAnywhere Hero 的单图编码、四图匹配、元数据代价体、融合 Transformer 与 DPT 主解码，不是独立自研架构。自研匹配图仍为 512×896、192 个深度格；上述基线匹配图为 256×448、64 个深度格。两者输出同一相机深度，但内部计算预算和附带输出不同。

**真正的主要加速项是官方 `cost_volume.to_fast()`：** 把深度维的匹配 MLP 从 64 次调用向量化成 1 次，保留格点和权重，减少重复构造及小算子调用。在本轮共享封装中，匹配 ResNet 仍分别执行四次，因此不能把收益归因为四图批量编码。缓存只复用冻结的位置编码，不缓存任何图像预测。

三帧输出一致性检查实际通过：

- 原适配器与共享封装的慢代价体主深度逐元素相同。
- 慢→快速代价体的最大差为 **0.000397 米**，逐帧平均差约 0.0000067–0.0000097 米，全部像素差小于 1 毫米；存在浮点运算顺序差异，不能写成逐元素相同。
- 去掉未使用的辅助多尺度深度／天空输出、位置缓存关闭→冷启动→热启动，主深度均逐元素相同；不同 RGB 的预测仍会变化。自研缓存开关也逐元素相同。

原始记录含逐次耗时、模型散列、源码散列及一致性结果：[执行对照](../../runs/active/latency_audit_20261022/execution_controls/summary.json)。本轮还保留了一个中止尝试：[原因记录](../../runs/active/latency_audit_20261022/execution_controls/interrupted_attempt.json)。该尝试错误地在 `inference_mode` 内构造模型，导致参数没有版本计数、缓存安全回退；发现后停止，改为仅在前向时开启该模式，并确认缓存确实生效后重新完整执行。中止尝试不作为测速结果。

## 3. 时间具体花在哪里

以下为独立插桩测量的 CUDA 事件中位数，仅用于定位模块；插桩有额外开销，不能直接代替上表无插桩的完整 forward 墙钟时间。

| MVSAnywhere 模块 | 慢代价体＋辅助输出 | 快代价体＋辅助输出 | 快代价体＋主输出＋缓存 |
|---|---:|---:|---:|
| 单图编码器 | 6.88 ms | 6.90 ms | 4.58 ms |
| 四次匹配编码合计 | 1.51 ms | 1.49 ms | 1.51 ms |
| 完整代价体 | 44.49 ms | 3.25 ms | 3.25 ms |
| 其中：匹配 MLP | 6.46 ms | 1.34 ms | 1.34 ms |
| 融合 Transformer | 10.76 ms | 10.72 ms | 8.37 ms |
| DPT 解码 | 4.61 ms | 4.60 ms | 3.17 ms |

**有父子包含关系的时间不能相加。** 例如 MLP 已包含在代价体内。自研也存在相同问题：

| 自研模块 | 时间 | 包含关系 |
|---|---:|---|
| `encoder.forward_features` | 9.75 ms | 包含 foundation 4.98 ms |
| 预训练匹配编码 | 3.50 ms | 独立于上述图像编码 |
| `coarse.forward` 两次合计 | 19.70 ms | stride16 为 5.19 ms；stride4 为 14.49 ms |
| `candidate_field.forward` | 28.66 ms | 包含第二次 coarse，以及 memory 12.59 ms |
| `dense_decoder.forward` | 25.29 ms | 包含 recover_initial 8.05 ms、refinement 7.42 ms |
| `raw_feature_reader` | 5.58 ms | 已包含在 recover_initial 内 |

当前自研的重要开销在细网格候选取证和多次后端修正，不是只把编码器做小就能解决。原自研 79.80→70.31 ms 的历史差额不能全部解释为缓存：本轮直接控制缓存只验证了约 2.58 ms 的差异，其余变化尚未逐项隔离。

自研实际调用 `encoder.forward_features`，会绕过普通 `module.forward` 钩子。因此最初普通钩子记录的编码器 0 次／0 ms 不表示编码器免费；已改用方法级计时，并验证插桩前后输出逐元素一致。以 [修正后的方法计时](../../runs/active/latency_audit_20261022/execution_controls/self_method_profile.json) 为准。

## 4. 既有六层学生：有速度价值，但不是精度全面持平

本轮只重新加载三个既有完整权重进行 DEV25 配对评测，没有继续训练、重新选权或再跑 TEST。共同有效 GT 为 2,087,873 像素，范围 2–80 米，预测覆盖率均为 100%。三者均使用官方快代价体、主 DPT 输出及相同位置缓存；GPU 6，FP32，TF32 关闭。计时仍用三个固定 DEV 帧，每帧预热 10 次、轮转计时 30 次，共 90 次。

| 固定权重方案 | 本轮 DEV MAE | 本轮 DEV RMSE | 本轮耗时 | 耗时倒数 |
|---|---:|---:|---:|---:|
| MVSAnywhere 原 CARLA 首遍基线 | 0.96201 m | 2.40687 m | 21.940 ms | 45.58 次/秒 |
| 既有十二层主输出头适配起点 | 0.82147 m | 2.20138 m | 21.916 ms | 45.63 次/秒 |
| 既有蒸馏六层融合学生 | 0.82986 m | 2.18073 m | **19.755 ms** | 50.62 次/秒 |

下表全部为 **此前固定权重的历史 TEST200 结果，本轮未重跑**。新速度与历史精度并列，仅用于定位已有权重的取舍，不是一次新 TEST 实验。

| 固定权重方案 | 历史 TEST MAE | 历史 TEST RMSE | 历史 AbsRel | 历史 ≤0.2 m 成功率 | 历史 24–80 m MAE |
|---|---:|---:|---:|---:|---:|
| MVSAnywhere 原 CARLA 首遍基线 | 1.12001 m | 3.46316 m | 0.05860 | 51.22% | 4.11796 m |
| 十二层适配起点 | 1.07103 m | 3.44894 m | 0.05422 | 53.14% | 4.05713 m |
| 六层融合学生 | 1.13237 m | 3.48706 m | 0.05901 | 47.01% | 4.23345 m |

六层相对原基线快约 **10.0%**，历史 TEST MAE 只差约 **1.1%**，可以保留为效率取舍对照。但 20 厘米成功率低 **4.21 个百分点**，远距 MAE 高约 **2.8%**，不能说所有精度持平。相对更强的十二层适配起点，历史 TEST MAE 退化约 **5.7%**，因此旧实验将其判为“未保住适配精度”是成立的；这不等于它完全没有速度对照价值。没有预设等效容差或统计检验，数值接近也不代表统计等效。

该学生仅执行官方融合层 `[0, 2, 5, 6, 8, 11]`，保留已有蒸馏与适配权重。单图十二层 ViT、匹配通路和 DPT 仍在，所以融合减半只带来约 2.16 ms 的完整网络节约。checkpoint 仍保存全部十二层参数，不能宣称文件、参数量或显存减半。**这是一条 MVSAnywhere 派生压缩路线，不属于自研标尺架构的原创成果。**

证据：[本轮 DEV、计时及实际层调用](../../runs/active/latency_audit_20261022/compact_reference/summary.json)、[新 DEV／历史 TEST 对齐表](../../runs/active/latency_audit_20261022/compact_reference/comparison_with_historical_test.json)、[历史 TEST 原汇总](../../runs/active/initial_architecture_followup_20261020/comparison_summary.json)。各 checkpoint 路径与散列均记录在本轮结果和配置内。
