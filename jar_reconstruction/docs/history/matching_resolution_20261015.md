# 低分辨率场景编码与高分辨率匹配

> 历史版本说明：保留设计与诊断依据；旧缓存和部分旧命令已归档。日常运行使用[当前配置](../../configs/current/README.md)，恢复方法见[整理记录](project_cleanup_20261019.md)。

这是可选的独立分支，不增加相机、标签、学习参数，也不扩大ViT或解码器。目的是把计算量优先用于容易丢失的小纹理对应关系，而不是让整个网络都处理更大的图像。

已经完成同一训练权重的DEV25全图比较：保持低分辨率场景编码与两轮细化，只提高匹配图分辨率，MAE从1.2731米降至1.1022米，20厘米成功率从38.50%升至42.69%，远距MAE从3.1487米降至2.5317米。这是DEV上的固定权重探索，不是独立数据泛化结论。低分辨率对照与高匹配分支各追加400步的实验正在进行，本文不预判其结果；完整记录以总体报告（历史内容已归档，见[整理记录](project_cleanup_20261019.md)）为准。

## 数据与尺寸

```json
"data": {
  "image_size": [256, 448],
  "matching_image_size": [512, 896]
}
```

CARLA读取器对每张原始RGB读取一次，分别缩放到上述两种尺寸。高分辨率图不是由低图放大得到的；推理不读取高分辨率深度或其他标签。

| 数据或模块 | 尺寸示例 |
|---|---|
| 场景RGB | `[B,4,3,256,448]` |
| 匹配RGB | `[B,4,3,512,896]` |
| 冻结Hero描述子 | `[B,4,16,128,224]` |
| 场景CNN、ViT、候选查询与解码器 | 保持原低分辨率配置 |

新增输入字段为 `matching_rgb` 和 `matching_image_mask`。缺失或主动禁用的相机，其两种RGB分支都被屏蔽；不会复制其他相机填充。原 `rgb/K/T_cam_from_rig/image_mask` 仍对应低分辨率场景坐标。

## 坐标关系

模型显式生成 `_pretrained_matching_scale: [B,2]`，顺序为宽度比、高度比。低图位置映射到匹配图：

```text
u_match = (u_low + 0.5) * (W_match / W_low) - 0.5
v_match = (v_low + 0.5) * (H_match / H_low) - 0.5
```

然后按Hero原生 `1.5 + 4*j` 中心读取描述子。实现合并这两次变换，不重新预测或自由修改相机参数。粗匹配和预训练描述子细化均传递该比例。

本轮只替换实际读取的描述子：参考查询仍使用原低图格点，投影导数、步长及已有几何元数据仍采用原低图像素单位。没有把原stride4查询改成stride2，以免混入额外改动。

## 支持范围与评测接入

目前要求显式 `camera.mode=wide4`、开启稠密头，并关闭稀疏头和 `feature_exchange`。这些分支仍有其他描述子读取路径，暂不允许静默错误采样。必须实际开启 `matching_evidence` 或使用预训练描述子的稠密细化，否则高图没有用途，构造模型时会报错。

正常训练直接使用模型配置的 `data.matching_image_size`。共同DEV评测还需在独立协议文件的 `data.matching_image_size` 中设置同样尺寸；`comparison_dataset` 会传给读取器。不要修改共同默认协议来影响其他方法。

不设置该字段时，数据、匹配采样和模型默认路径保持原行为。启用后如果推理缺少配置尺寸的 `matching_rgb`，会明确报错，不会从低图静默放大。

合成数据接口可以把同一渲染RGB缩放成两种输入以验证张量与坐标。这种插值测试不能证明新增了纹理，也不能作为高分辨率收益实验；实际性能比较应使用真实原图的两次独立缩放。

所有新增数据均位于 `inputs`。标签仍留在 `targets`，真实无标签读取模式不打开标签文件。模型权重结构没有变化，可严格加载现有检查点。不同输入分辨率的精度、延迟与显存需要在实际实验中单独记录。

## 实际CPU验证

```bash
official_methods/.venv/bin/python -m pytest tests/test_matching_resolution.py -q
```

实际结果为 **7 passed，无skip**。测试使用本地真实Hero缓存，覆盖比例1、比例2和各向异性比例的采样值及坐标梯度；磁盘原图两次独立缩放、缺失相机、高图有效掩码、K/T和无标签读取；旧worker数据对象缺少新属性时的兼容；以及具有真实投影关系的四目渲染图上完整模型前后向。测试直接检查粗匹配和细化采样都收到正确比例，不能仅由输出张量尺寸推断接线正确。

此外，原多焦距数据、预训练匹配、匹配证据、稠密细化和蒸馏回归实际通过61项及2个子测试。CPU tiny测试只证明接口、部分几何和梯度逻辑可用，性能结论以上述DEV实验及总体报告为准。
