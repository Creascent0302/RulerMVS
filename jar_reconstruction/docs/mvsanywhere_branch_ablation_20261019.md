# MVSAnywhere 初始深度的分支干预与自研架构对照

本报告的直接结论是：**在当前 CARLA 权重和冻结权重的屏蔽实验中，多视图 ResNet 描述子被屏蔽造成的误差增量更大；单图 ViT 也不可缺少。两边的差距不能解释成“自研没有 Depth Anything 编码器”。自研实际已经使用与原始 Hero 完全相同的单图编码器和匹配编码器权重，差别集中在提取特征之后的证据表达、联合推理、解码及其训练。**

这里做的是推理时的特征屏蔽、错位及权重替换，没有重新训练被屏蔽的网络。它回答“现有模型依赖什么”，不能直接回答“重新训练的纯单图模型或纯多视图模型最终能达到多少”。所有表格都是实际运行结果。

## 1. 比较对象与实验边界

- 输入固定为同一时刻四台广角相机，RGB 为 256×448，已知米制标定；只预测和评价上相机。自研匹配分支另读取同四张原图的 512×896 版本。
- MVSAnywhere 使用官方 Hero 原生模块。分别评价原始 Hero 预训练权重，以及项目已核查的 CARLA 微调权重。关闭二次范围重估，只测试首遍。
- 使用 DEV25 和另一轨迹 TEST200；两个权重版本共 450 帧。TEST200 此前已用于研究诊断，不能称为全新盲测。
- 主表在共同步长 4 格点上计算初值 MAE：64×112、2–80 米、相同真值 ROI、像素加权聚合。全图指标另存，不混用。
- 每次干预都保持同一帧的搜索范围、标定、参考图和输出网格不变。标签仅在所有前向完成后用于评价，没有按预测置信度删去难像素。所有主消融的评价覆盖率均为 100%。
- 此处“Hero 初值”是**完整 Hero 深度解码输出在步长 4 网格上的取样**，不是其代价体直接取最大分数的深度。自研初值指 K9 重选后、局部细化前的深度。

实际权重：

| 对象 | 路径 |
|---|---|
| 原始 Hero | `runs/carla_research_20261011/cache/mvsanywhere_hero.ckpt` |
| CARLA 微调 Hero | `runs/mvsanywhere_audit_20261013/finetune_verified/last.pt` |
| 当前自研模型 | `runs/candidate_revision_20261018/metric_supported_k9_train220_consensus.pt` |

## 2. 如何隔离两种信息

**屏蔽单图 ViT**：将它向融合器提供的六组 patch/class token 置零。代价体、四目 ResNet 描述子、标定、第二个融合 ViT 和 DPT 解码器保持原样。

**屏蔽 ResNet 描述子**：将参考及三个源视图的匹配描述子置零，然后由原生投影与元数据 MLP 重建代价体。单图 ViT 保持原样，射线、姿态、候选深度和几何有效性仍保留。因此这比把整个代价体直接清零更精确地针对 ResNet 图像信息。

**屏蔽整个代价体**：只把送入融合器的候选体置零，单图特征保持真实值。用于核对仅保留元数据是否改变结论。

**错位对照**：保持特征值的集合不变，将单图 patch token 或源图描述子循环平移三分之一网格，破坏空间对应关系。单图错位保留 class token。此项是人为的对应关系破坏，不等于真实噪声或缺相机测试。

网络内部会对零输入继续施加可学习偏置、归一化和后续推理。因此“屏蔽单图”不意味着删除了所有曾从单图训练学到的知识，“屏蔽代价体”也不等于一个单独训练的最佳单目模型。两组原始/微调权重、屏蔽与错位共同用于减少对单一干预形式的依赖。

## 3. 主要结果：哪条路径影响更大

单位均为米，初值 MAE 越低越好。

| 干预 | 微调权重 DEV25 | 微调权重 TEST200 | 原始 Hero TEST200 |
|---|---:|---:|---:|
| 完整 Hero | 0.965 | **1.106** | **1.460** |
| 屏蔽单图 ViT 特征 | 2.652 | 3.309 | 4.259 |
| 屏蔽四目 ResNet 描述子 | 11.012 | 8.083 | 7.675 |
| 两者同时屏蔽，保留元数据 | 11.245 | 9.678 | 9.613 |
| 屏蔽整个多视图候选体 | 10.891 | 7.967 | 7.620 |
| 单图特征空间错位 | 12.460 | 8.887 | 13.946 |
| 三个源视图描述子空间错位 | 8.719 | 5.443 | 6.478 |

在当前微调模型 TEST200 上，屏蔽单图特征使误差增加 **2.204 米**，屏蔽 ResNet 描述子使误差增加 **6.978 米**。以这种特定的冻结权重屏蔽方式衡量，后者误差增量约为前者 **3.17 倍**。这不是两者的固有贡献比，也不能写成“多视图贡献 76%、单图贡献 24%”。两条信息在同一个融合器中相互作用：同时屏蔽的增量为 8.573 米，不能由两个单项增量直接相加得到。

原始 Hero 不经过 CARLA 微调也有同一趋势：单图屏蔽增量 2.798 米，描述子屏蔽增量 6.215 米。微调版本的 TEST200 中，两种单项屏蔽在全部 200 帧上都比完整模型差，并非单个异常帧主导。

空间错位给出另一个结论：错误单图结构比缺少单图结构更危险。微调版本单图置零为 3.309 米，单图错位为 8.887 米；因此不能仅根据“单图置零损害较小”就让单图先验无条件主导。错位干预中单图损害反而大于源描述子错位，说明“哪条更重要”的排序依赖干预方式，不能普遍化。

### 中远距离

| 微调版本 TEST200 | 2–10 m | 10–24 m | 24–80 m |
|---|---:|---:|---:|
| 完整 Hero | 0.243 | 0.986 | 4.061 |
| 屏蔽单图特征 | 1.224 | 2.279 | 11.630 |
| 屏蔽 ResNet 描述子 | 3.209 | 8.037 | 23.791 |

两者在远距离都很重要；当前数据上不能靠单图先验替代真实多目对应。完整 Hero 的远距离误差本身也尚未达到 0.5 米目标。

## 4. 关键反证：自研已经有相同的 Depth Anything 来源特征

逐张量比较当前自研 checkpoint 与原始 Hero：

| 自研模块 | 比较张量数 | 不相同张量数 | 最大绝对差 |
|---|---:|---:|---:|
| 冻结单图 ViT-B | 175 | **0** | **0** |
| 冻结 ResNet 匹配编码器 | 35 | **0** | **0** |

这些是 Depth Anything 初始化、随后参与 Hero 训练的编码器权重，不是另一个同名但较弱的随机网络。

进一步使用 DEV 第 0 帧与 TEST 第 0 帧、完全相同的参考 RGB，比较自研输出与原始 Hero 相应层的原始 patch 特征。第 3、6、9、12 层全部为 `[1,448,768]`，八组张量均逐元素相同，最大绝对差 **0**。核对位置在通道压缩、门控和特征重采样之前；没有把后续不同处理误当成编码器不同。

### 把 Hero 的图像提取器换成自研正在使用的权重

保留微调 Hero 的融合器与 DPT，只将提取器恢复为原始 Hero 权重，也就是自研实际使用的权重。TEST200 结果如下：

| 设置 | 初值 MAE |
|---|---:|
| 完整 CARLA 微调 Hero | 1.106 |
| 单图编码器恢复为自研同款权重 | 1.383 |
| 匹配编码器恢复为自研同款权重 | 1.082 |
| 两个编码器都恢复为自研同款权重 | **1.366** |
| 自研学习初值，K9 之前 | 3.246 |
| 自研 K9 之后、细化之前 | **2.519** |

单图编码器的 CARLA 微调对 Hero 有约 0.278 米的条件收益，不能说权重适配毫无影响；匹配编码器微调则没有在这条轨迹上带来收益。两种提取器均相同后，Hero 仍比自研 K9 初值低 **1.153 米**。因此提取器权重差异不能解释全部差距。

这仍不能把这 1.153 米全部算成纯架构收益：Hero 的元数据 MLP、融合器和 DPT 有大量 MVS 任务预训练，自研对应部分主要在少量 CARLA 数据上学习。已排除的是“只有图像提取 器是否使用 Depth Anything”这个解释，而没有排除其余模块的预训练和数据优势。

## 5. 自研是否没有真正用到这些特征

自研只对稠密解码器接收的单图上下文置零，保留原 CNN、候选场和匹配特征：

| 自研设置 TEST200 | 学习初值，K9 前 | K9 后 |
|---|---:|---:|
| 正常上下文 | 3.246 | 2.519 |
| 单图上下文置零 | 8.671 | 7.287 |
| 单图上下文错位 | 16.520 | 15.626 |

自研显著依赖这些上下文，并非没有接上、完全没用或者所有门控都关闭。门控值约 0.032–0.044，也不能单凭幅度小就断言特征被忽略：后续有 GroupNorm，会改变幅度的实际意义。当前证据更支持“已有强先验，但将它与几何证据转成准确深度的能力不足”，而不是“缺少强先验”。

## 6. 两种初值网络具体不同在哪里

两者抽象上都是“图像特征 + 标定匹配 + 解码”，但这一级描述无法说明网络是否有相同能力。以下是**当前实际启用的稠密分支**；自研早期的稀疏层级查询解码器关闭，没有参与本次成绩。

| 环节 | MVSAnywhere Hero | 当前自研模型 |
|---|---|---|
| 单图原始编码 | ViT-B，768 维；CARLA 可微调 | 同款原始 Hero ViT-B，768 维，冻结 |
| 取出的图像层 | 第 1/3/5/6/9/12 层 | 第 3/6/9/12 层 |
| 如何使用匹配描述子 | 参考及源图各 16 维向量连同几何信息送入 MLP，逐源图预测分数与权重 | 主要转换为归一化余弦相似度、均值/方差及逐源相似度，再配合局部 CNN 相关性 |
| 初值的候选输入网格 | 真实 stride-4 匹配证据，64 深度候选 | 主解码候选包默认 stride 16，192 候选；另有 stride-4 候选场用于重选和细化 |
| 单图特征压缩 | 浅层分支投影到 96/192 维；深层注入仍为 768 维 | 各层先从 768 压到 32 维，再适配到 64 维解码空间 |
| 何时融合 | 候选体卷积下采样时融合浅层图像信息；第二个 ViT 的四个位置再融合深层图像信息 | 小型候选包编码和两层 64 维 Transformer 后，与图像上下文在四级 CNN 解码中拼接融合 |
| 候选联合判断 | 独立的 12 层、768 维融合 ViT，再接 DPT | 候选上下文 2 层、64 维；各尺度 2 个残差图像块；另有小型候选记忆/K9 选择头 |
| 解码学习来源 | 融合与深度解码经历完整 MVS 任务预训练，再 CARLA 微调 | 主要继承图像提取器；融合/稠密深度头为自研，在少量 CARLA 数据上学习 |

实际参数量：Hero 单图编码器 8658 万；匹配编码器 **18.4 万**；元数据 MLP **2626**；候选体融合模块 **1.034 亿**；DPT **1154 万**。自研整个稠密解码器约 **91.3 万**，候选场小头约 **1620**。参数少并不自动说明性能差，但两者显然不是只差一个编码器名称。

### 差异一：同样的描述子，保留的信息不同

把两个 16 维向量压成一个相似度后，能保留“看起来多像”，但失去“具体是什么特征模式”和向量幅度等信息。多个不相同的描述子对可以得到同样相似度，后续层无法仅靠这个标量恢复被压缩的内容。Hero 的逐源 MLP 可结合完整描述子与几何信息学习哪些匹配可靠；自研当前更依赖相似度统计和几何候选场。该信息限制是结构事实；它实际解释多少米，还需要同训练预算、保留完整向量的受控改动验证。

### 差异二：在候选判断时，先验参与的程度不同

Hero 不只把单图特征附加给最终输出头，而是让其参与候选体转换和多轮联合推理。自研用于学习初值的主通路把候选证据包压入 64 维，再进行较轻量的上下文与解码；另外的候选场仍保留深度维度，不能说所有候选都被提前丢弃。

两边都是特征融合，但“保留较多内容，反复联合判断”和“先强压缩，再由小解码器学习恢复深度”有不同的信息与学习负担。不能从本次屏蔽直接证明增加通道必然有效；已验证的是同一套强特征在两个后端中确实产生了不同水平的初值。

### 差异三：我们称为初值的 Hero 结果，已经经过完整深度估计

微调 Hero 原始候选体直接取最大分数，再映射到公共网格，TEST200 MAE 仍为 **5.741 米**；完整融合和解码后为 **1.106 米**。前者只作阶段诊断：MLP 的候选体输出是后续网络的输入，不保证是校准的独立深度概率；其重采样也可能平滑边界。因此不能把 4.635 米差值逐模块分摊。

但这个结果说明：Hero 的优势不能简单描述为“第一步匹配直接找到了非常精确的表面”。它的重要能力是在整幅图像结构和候选证据之间联合解释。此前将完整 Hero 输出接到自研细化器前，实质上是让完整深度网络帮助自研选面。

## 7. 融合位置的额外干预：优先保留哪部分

| 微调 Hero TEST200 | 初值 MAE |
|---|---:|
| 完整 | 1.106 |
| 只屏蔽用于候选体转换的前两组单图特征 | 1.099 |
| 只屏蔽后四组深层注入特征 | 3.273 |
| 六组全部屏蔽 | 3.309 |

当前数据与权重下，单图先验的影响主要来自深层 token 注入；浅层注入屏蔽后只有毫米级差异。原始 Hero 的 TEST200 也有相似趋势：屏蔽前两组为 1.460，屏蔽后四组为 4.249，完整为 1.460。

这支持把下一次优化重点放在“低分辨率下的语义结构与几何候选联合判断”，并优先检验现有浅层融合是否值得其计算。它尚不证明可以无代价删除所有浅层结构：置零仍保留偏置和后续卷积，且未重新训练或跨数据集验证。

官方论文也有**重新训练后的消融**：表 4 中，去掉 DAV2 初始化、改用 DINOv2 时，平均相对误差从 3.00 变为 3.24；用 CNN 替换单图/多图融合 ViT 时为 3.41。这些是论文自己的低分辨率、无 metadata 设置，不能与本报告的 CARLA 米制 MAE 混比，但支持“编码器预训练和融合结构都重要”。依据：[论文表 4](https://arxiv.org/html/2503.22430v1#S4.T4)、[官方融合代码](https://github.com/nianticlabs/mvsanywhere/blob/main/src/mvsanywhere/modules/vit_modules.py)。论文描述的融合层编号与代码有一处差异；本报告按实际代码的零基编号 `[2,5,8,11]` 执行。

## 8. 对后续自研修改的约束

1. **不再把换一个同款单图编码器作为主方案。** 已经逐权重、逐特征验证相同，重复搬同一提取器无法填补后端能力。
2. **优先比较信息保留和融合时机。** 在相同冻结编码器、相同 CARLA 划分下，对比“完整匹配向量/几何条件评分”与现有相似度统计；对比在形成候选表面前读取较完整单图 token，与当前先压缩后的融合。先做小规模受控训练，不直接堆第二套完整大网络。
3. **明确区分结构与后端预训练。** 如采用预训练 DPT 或融合层，应单列初始化来源；若要宣称纯结构收益，需匹配其余训练条件。
4. **错误先验需要拒绝机制。** 本次错位结果说明错误结构能严重压倒真实匹配；可研究由多视图证据决定单图注入位置与强度，而非无条件加权。这是下一轮假设，尚未证明能改善当前指标。
