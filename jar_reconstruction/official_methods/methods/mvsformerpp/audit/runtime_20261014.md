测试首次GPU跨batch比较受到默认cuDNN TF32影响，最大绝对差约0.00254米、相对差约0.000233；禁用TF32后原定容差通过，没有通过放宽断言掩盖索引问题。相同batch的官方原生调用与适配器仍逐值一致。

原生重入gradient checkpoint与DDP `find_unused_parameters=True` 不适合组合。本模型已经验证全部可训练分支有梯度，适配器显式设置False，实际双卡训练/恢复通过。推理使用batch1时与原生兼容；不同标定批量推理仍继承官方3D位置编码跨batch极值归一化行为，不保证完全独立。

## 运行命令

以下路径以项目根 `jar_reconstruction` 为起点。权重均存放在 `runs/deep_architecture_20261014`，它实际指向 `/data/liuzonghao_data/3Dscene_runs/deep_architecture_20261014`。

```bash
OMP_NUM_THREADS=2 official_methods/.venv/bin/python -m pytest -q official_methods/tests/test_mvsformerpp.py
CUDA_VISIBLE_DEVICES=7 MVSFORMERPP_TEST_DEVICE=cuda OMP_NUM_THREADS=2 \
  official_methods/.venv/bin/python -m pytest -q official_methods/tests/test_mvsformerpp.py
OMP_NUM_THREADS=2 official_methods/.venv/bin/python -m pytest -q official_methods/tests/test_method_packaging.py

CUDA_VISIBLE_DEVICES=7 OMP_NUM_THREADS=2 bash official_methods/scripts/run.sh mvsformerpp train \
  --config official_methods/methods/mvsformerpp/configs/carla_smoke.json \
  --output runs/deep_architecture_20261014/mvsformerpp_carla_smoke --device cuda
CUDA_VISIBLE_DEVICES=7 OMP_NUM_THREADS=2 bash official_methods/scripts/run.sh mvsformerpp evaluate \
  --config official_methods/methods/mvsformerpp/configs/carla_smoke.json \
  --checkpoint runs/deep_architecture_20261014/mvsformerpp_carla_smoke/last.pt \
  --output runs/deep_architecture_20261014/mvsformerpp_carla_smoke/evaluation \
  --max-batches 1 --device cuda

CUDA_VISIBLE_DEVICES=6,7 GPUS=2 OMP_NUM_THREADS=2 bash official_methods/scripts/run.sh mvsformerpp train \
  --synthetic --config official_methods/methods/mvsformerpp/configs/synthetic.json \
  --output runs/deep_architecture_20261014/mvsformerpp_ddp_smoke --device cuda
CUDA_VISIBLE_DEVICES=6,7 GPUS=2 OMP_NUM_THREADS=2 bash official_methods/scripts/run.sh mvsformerpp train \
  --synthetic --config official_methods/methods/mvsformerpp/configs/synthetic_resume.json \
  --checkpoint runs/deep_architecture_20261014/mvsformerpp_ddp_smoke/last.pt \
  --output runs/deep_architecture_20261014/mvsformerpp_ddp_resume --device cuda
```

恢复测试为了执行额外一步，将配置总步数由2改为3，因而不能声称与从零规划三步的学习率序列相同。本测试确认checkpoint的加载与继续训练能力。

## 原始源码一致性

官方仓库在 `/tmp/mvsformerpp_research_20261014`，提交 `bdd980cfbae9a863b5489e2ed973612b192d11a5`。实际用两个独立Python进程构造官方/适配模型，以seed1701相同初始化、相同真实投影关系的合成四目输入，在CPU比较26个原生输出。结果为 [`native_parity_20261014.json`](native_parity_20261014.json)。同样独立加载未修改官方 `losses.py` 比较密集和稀疏监督，结果为 [`loss_parity_20261014.json`](loss_parity_20261014.json)。

可用随附脚本重跑前向对照：

```bash
official_methods/.venv/bin/python official_methods/methods/mvsformerpp/audit/native_parity.py \
  --source /tmp/mvsformerpp_research_20261014 \
  --output /tmp/mvsformerpp_native_parity_repeat.json
```

完整权重加载接口采用strict=True，但尚无官方任务权重，故“完整官方发布权重加载成功”未验证。随机架构的checkpoint重载成功不能替代这一项。
