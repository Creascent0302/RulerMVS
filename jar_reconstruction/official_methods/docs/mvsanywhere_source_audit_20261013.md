# MVSAnywhere 官方源码一致性审计（2026-10-13）

本轮重新从官方仓库完整克隆源码，以独立副本核查现有实现。结论是：项目确实使用官方 **Hero 完整网络**，没有用 dot 消融、轻量替代网络或自研预测头冒充。此前的兼容补丁在一种稀疏监督情况下改变了梯度损失，本轮已经修正。CARLA 的数据、分辨率、训练预算与原论文不同，因此应称为“官方 Hero 的 CARLA 适配和微调”，不能称为原论文指标复现或原模型零样本结果。

本页负责源码、架构、配置与补丁取证。独立 GPU 输出比对、微调及恢复训练结果由本轮运行报告记录；不能把源码比对通过理解为所有训练、数据标签或论文指标已经验证。

## 3. Hero 的核心模块逐项对应

下面的“相同”指固定提交中的真实实现，而非只参考论文摘要重写的近似结构。

| 流程 | 官方实现与本地核查 |
|---|---|
| 输入 | 参考 RGB + 源 RGB + 已知内外参；四目为一张参考、其余三张源图，没有复制或增加历史帧 |
| 匹配编码器 | `ResnetMatchingEncoder`，抗混叠 ResNet18 的浅层，加 128 通道中间层及 16 通道匹配特征，输出为原图 1/4 |
| 深度候选 | `CostVolumeManager.generate_depth_planes`，默认 64 个对数间隔候选；没有改成逆深度或线性间隔 |
| 元数据匹配 | `ViewAgnosticFeatureVolumeManager`，46→32→32→2 的共享 MLP，每个源视图输出分数和权重；沿源视图维度 softmax 后加权汇总 |
| 单目先验 | `DINOv2` ViT-B；只输入参考图，先缩放 14/16，完整 12 个 Transformer 块，没有替换为项目共享 FPN |
| 成本体分块 | `CostVolumePatchEmbed`，分阶段卷积及两次浅层参考特征注入；不是把成本体直接平均成深度 |
| 单/多目融合 | 第二个完整 ViT-B，即 `ViTCVEncoder`，逐位置注入参考特征；保留 CLS、位置编码及原生层连接 |
| 深度输出头 | 官方 `DPTHead`，保留四尺度深度与天空分支；不替换为统一 baseline 头 |
| 米制输出 | 深度头在当前最小/最大深度的对数范围中预测连续位置，然后取指数得到相机 Z-depth |
| 推理范围 | 保留官方标定启发式及基于第一次预测的范围修正；默认额外细化一次 |

“64 个候选”是构造匹配证据的范围，不表示最终输出只能落在 64 个离散深度上。各相机结果轮换参考视图分别生成，四参考场景开销必须计入四次调用。

官方网络源码入口为 [sr_depth_model.py](../methods/mvsanywhere/upstream/src/mvsanywhere/experiment_modules/sr_depth_model.py)。匹配 MLP、投影和 DPT 的实现均来自原仓库。

## 4. 附件说明中需要精确理解的地方

附件对主要流程的解释与所选代码基本一致，但教学说明不能替代固定版本源码。

- 元数据中的深度归一化确实是 `(depth - min_depth) / max_depth`，不是除以范围宽度。虽然其他写法也可能合理，忠实 baseline 不自行更换。
- 所选 ViT-B 单目中间层是 `[0, 2, 4, 5, 8, 11]`。前两层用于成本体分块；后四层分别在第二 ViT 的 `[2, 5, 8, 11]` 块之前注入，再在这些块之后取输出。论文文字出现 `[2, 5, 9, 11]`，本地采用明确固定的官方代码，不凭文字改连接。[论文](https://arxiv.org/html/2503.22430v1#S3.SS3)
- 官方主模型是 `mvsanywhere_hero.ckpt`；`mvsanywhere_dot.ckpt` 是去掉 metadata MLP 的消融。项目选择 Hero，并以完整权重严格加载验证各模块。仅使用 DA V2 或 DINOv2 骨干权重不等于加载完整 Hero。[官方权重说明](https://github.com/nianticlabs/mvsanywhere#-pretrained-models)
- 深度损失类中虽然定义了 `MVDepthLoss`，但此版本的最终总损失不包含该项。因此 CARLA 缺源图深度标签，不应凭空为 MVSAnywhere 加一项跨视图深度监督。

## 5. 本轮发现并修复的真实偏差：稀疏梯度监督

此前补丁把 `MSGradientLoss` 的每个空尺度分别当作零，然后继续累加其他尺度。这对完全密集的监督没有影响，但**某些尺度有有效标签、较粗尺度没有有效标签**时，并不等价于原实现。

官方代码会在空尺度得到 NaN，使整个多尺度梯度项成为 NaN，再由外层 `compute_losses` 的 `nan_to_num` 将整个项置零。此前本地实现则保留了其他尺度的非零梯度项。独立审计构造的稀疏案例中，原始项为 0，本地旧补丁约为 0.000233，证明之前“有效监督上的行为全部未变”的笼统说法不成立。

现已改为：只要某个尺度没有有效梯度监督，返回与预测计算图相连的零，匹配官方完整损失的最终数值与反向行为。这项修复是为了忠实复现，不是为了提高 baseline 指标；若研究更合理的稀疏监督目标，应另设方法或消融，不能偷偷改官方 baseline。

独立 CPU 损失测试已实际通过，使用 pristine 的原损失类/`compute_losses` 与本地各自实现；只把官方硬编码的 `.cuda()` 设备调用替换为 CPU 恒等操作，不修改公式：

| 监督样例 | 官方总损失 | 修复后本地总损失 | 预测梯度最大差 |
|---|---:|---:|---:|
| 密集深度 | 0.3499965668 | 0.3499965668 | 0 |
| 密集深度及天空 | 0.5960617065 | 0.5960617065 | 0 |
| 稀疏深度块 | 0.3395848870 | 0.3395848870 | 0 |
| 全空监督 | NaN | 0 | 0 |

全空监督并非逐项数值相同，而是明确的安全扩展：适配器在无监督时直接返回零，不让无效 batch 污染参数。测试还把源图深度值从 1 改为 1234，损失和梯度没有变化，符合该版本总损失没有使用源图深度的事实。

报告：[loss_parity_20261013.json](../methods/mvsanywhere/audit/loss_parity_20261013.json)。复跑命令：

```bash
official_methods/.venv/bin/python -m official_methods.tests.mvsanywhere_loss_parity \
  --official-source /tmp/mvsanywhere_official_audit_20261013 \
  --output official_methods/methods/mvsanywhere/audit/loss_parity_20261013.json
```

已完成的旧微调结果来自旧代码，应保留其来源；后续实验以修复后的源码哈希区分，不能覆盖旧结果后声称一直相同。

## 6. 训练保留了什么，CARLA 改变了什么

当前原生总损失为四尺度 log-L1，加逆深度梯度、法线和权重 0.1 的天空损失。尺度权重为 `1, 1/2, 1/4, 1/8`。缺天空标签时该项无监督，不以“大深度”偷偷生成天空真值。有效训练标签按 CARLA 共同协议截取；无标签区域保持未知。

原生优化器的三组参数分别为：匹配网络/元数据 MLP（学习率 `1e-4`）、参考 ViT（`5e-6`）、成本体 ViT 与解码器（`5e-5`），均为 AdamW、权重衰减 `1e-4`。本地把三个互不相交的优化器合为三个参数组，采用对应的学习率计划；只要更新次数、梯度累计和梯度处理相同，逐参数更新公式相同。不能由“公式相同”推导训练批次或最终效果相同。

官方代码每两个 microbatch 更新一次，匹配组在 70k/80k 次更新后降档，另外两组在 70k 更新内线性衰减。Lightning 手动三个优化器的 `global_step` 与统一 runner 的单次 optimizer update 不是同一种计数；`Options.max_steps=220000` 不能直接解释成 220000 次本地联合更新。

审计开始时已有的 CARLA 微调配置 `configs/carla_comparison/mvsanywhere.json` 与原训练不同：

| 项目 | 官方训练/参考 | 已有 CARLA 实验 |
|---|---|---|
| 数据 | 八个合成数据集及其 tuple 策略 | 用户采集的同步四目 CARLA |
| 视图 | 默认总共 8 视图 | 同一时刻 4 视图，参考上目 + 3 源图 |
| 图像 | 480×640 | 256×448 |
| 初始化 | DA V2 / DINOv2 / 匹配骨干初始化后训练 | 严格加载完整官方 Hero 后微调 |
| 每卡 batch | 官方 README 示例为 6 | 1 |
| 梯度累计 | 2 | 旧实验为 1；本轮配置以实际运行记录为准 |
| 训练预算 | 原多数据集训练 | 旧实验 1000 次联合更新 |
| 数值精度 | 官方配置为 16 位 | 旧 CARLA 实验 FP32 |
| 图像增强 | 原数据集专用裁剪、颜色与两类翻转 | 共同缩放，保留颜色增强与两类翻转，未逐一复刻原八数据集的裁剪策略 |
| 天空监督 | 数据集有标签时使用 | 当前 manifest 没有可确认的天空标签 |

这些差异应公开记录；不能通过修改网络让不同数据协议看起来相同。论文训练集、预训练与评测集也不同，因此 CARLA 微调结果与官方 RMVD 零样本表格不应直接混列为同一实验。[官方训练与评测入口](https://github.com/nianticlabs/mvsanywhere#-training)

## 7. 原仓库自身存在、但本轮不擅自改动的行为

1. `forward` 中的天空输出先经过 sigmoid，`compute_losses` 又调用 `binary_cross_entropy_with_logits`。本地保留该代码行为，不将其擅自“修好”后仍宣称原生相同。
2. 稀疏监督分支构造了 `depth_gt_grad`，但梯度损失实际仍接收原 `depth_gt`。这是固定提交的原始行为。
3. 逐深度循环中的 `overall_mask_bhw` 会被后一个候选覆盖，且深度有效性和图像边界分别沿视图取 any。它不是最终深度的可靠性、遮挡或空间占据真值。适配器保留原生字段，但没有把它伪装成置信度；公共 `depth_valid` 只说明输出有限且为正。
4. 官方数据层的几何翻转和模型内部的特征翻转是两种独立增强；本地同时保留并非重复调用错误。

## 8. 输入几何、推理边界与未验证事项

公共接口使用整数像素中心和米制 `T_cam_from_rig`；官方反投影网格使用半像素中心。适配器相应给主点加 0.5，再按特征尺度缩放，返回深度内参时转换回来。原生输出是相机 Z-depth，不是沿单位射线的距离。所有外参只组合/求逆，不优化标定。

训练范围扰动仅使用训练标签；`eval()` 强制重新根据标定估计范围。配置中共同评价范围 2–80 米不等于模型推理内部的硬范围。当前共同四目配置要求四台有效相机，缺失帧不会复制图像补齐；原模型支持可变源视角数，但缺视角批处理的额外协议不能被假定已实现。

这次审计不证明以下事项：原始 CARLA 深度文件的采集解码公式、原论文训练当天的所有依赖、原论文精度、未运行的 TSDF/高斯应用、完整大规模收敛或小障碍物性能。采集脚本仍在另一台电脑，深度解码来源尚待独立核对。推理应始终只接收 RGB 与标定，标签与输入保持分离。

源码许可证保留在 [官方 LICENSE](../methods/mvsanywhere/upstream/LICENSE)，其允许范围与限制不能自动替换成 DINOv2 的 Apache-2.0 许可证。现有官方方法说明里“未下载权重、未使用真实数据”等历史文字已不适合描述现状，应以本轮的代码、配置和实际报告为准。
