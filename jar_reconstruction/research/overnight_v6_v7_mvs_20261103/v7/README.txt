RulerMVS-V7：候选条件化的多层重新融合

本分支是在V6上新增的独立研究模块，模型标识rulermvs_v7_refusion。
它不同于旧research/v7_domain_20261102的已停止原型，不加载其权重。
不改V6源码，不调用MVSAnywhere模型或Hero权重，不复制完整代价体ViT。

为什么改这里
既有courtyard诊断表明错误在粗候选阶段已经出现；96刻度本身覆盖足够，
末端细化不足以纠正。旧的纯图像候选先验未得到普遍净收益，因此这次让
已取得的匹配证据先决定汇聚内容，反复读取图像层级后再回到原候选评分。
这是待验证结构假设；增加模块与短试通过不代表泛化已经提高。

默认256×448主图的数据流（B为batch，D=96）
1. 沿用V6编码、标定投影、源图注意力和局部候选卷积。
   粗候选特征[B,64,96,32,56]，未压成唯一深度。
2. 新query投影64→32，空间2×2带mask平均，不混深度轴。
   得到[B,32,96,16,28]。每12个连续log深度候选组成一个带，共8带。
3. 在每带内用内容注意力汇聚，但保留原96候选query作为返回通路。
   汇聚附带null质量及log(1+Σw|d像素/d深度|²×候选半宽²)。
   后者是无量纲投影足迹，不是纹理强度或匹配正确性的证明。
4. [B,8,16,28,32]上下文经过两轮重融合：第一轮读取DA前两层，
   第二轮读取后两层。各层沿用V6的768→128适配结果，再融合为32维。
   每轮先融合图像和候选证据，再对同深度带的448个二维格点做4头
   attention，随后小FFN。八个带共享参数，彼此不在这里平均深度。
5. 带上下文回到32×56；原96候选query分别与所属带上下文点积。
   得到[B,96,32,56]评分残差，tanh限幅±4。零初始化输出投影使
   初始函数与V6相同。首步学习输出投影，随后整条支路获得梯度。
6. 修正后的粗候选分布进入原V6四族选取、细格取证、交接和上采样。
   不添加投影，不重算编码器，不新增细层修正头。

复杂度与局限
新增43233参数。attention复杂度随8×(H/16×W/16)²增长，不在全候选体
上做attention；本轮256×448尺寸较低，未来高分辨率须重新检查时间。
深度带汇聚仅传递上下文，不能保证保留每个峰的全部信息；跨边界全局
消息可能错误，故原候选路径保留、评分有界且可关闭。该模块没有解决
V6所有内部单位依赖，也未声称单独修复真实域泛化。

接口
from research.overnight_v6_v7_mvs_20261103.v7.model import V7Model, model_factory
config['architecture'] = 'rulermvs_v7_refusion'
config['refusion'] = {'enabled': True, 'hidden': 32, 'heads': 4, 'bands': 8,
                      'maximum_score_change': 4.0}
V7Model(config, initialize=True)只用原V6允许的DAv2与ImageNet初始化。
load_v6_state(state)严格加载V6底座，新增支路维持自身初始化。
decoder.refusion.enabled=False可在推理时完全跳过新支路。
所有新增参数位于decoder.refusion.，从头训练建议使用decoder相同学习率；
成熟V6暖启动时应单独为新支路设学习率，避免采用极小成熟头学习率。
